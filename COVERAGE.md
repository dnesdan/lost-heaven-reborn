The static inspection route now uses the recovered clock, frame-delta modifier, frame coordinator, empty Scene, shared driver time and model dispatch. The separate position route also binds the recovered IPol control and position evaluator. Native comparisons cover 22,576 delta cases, 1,509 coordinator cases and six driver edge cases. Seven model-dispatch Rust tests project selected behavior from an 11-case native oracle; they are not a full 11-case state differential. The selected Game-loop controller has 123 native comparisons but is not the application's full loop: mission initialization, input helpers and original list population remain open.

The complete static REA sweeps retain 4,783 Game.exe entries and 1,530 LS3DF.dll entries. Supplied configuration Setup.exe has 172/172 recognized non-thunk procedures retained; the separate installer bootstrap has 376/376. The baseline REA profile fails at Game entry VA `0x4ab910` with “cannot properly adjust input varnodes.” A separate direct Ghidra experiment corrects the prototype from instruction/caller evidence and produces pseudocode with 14 warnings, preserving the original body and inventory. Current REA tools do not support that prototype change; the alternate result is retained separately and does not change the audited totals or establish native behavior. Analyzer inventories include incomplete boundaries, warnings and external/thunk entries; these counts do not establish semantic recovery. Distribution prerequisite installers are separate from game-runtime reconstruction.
