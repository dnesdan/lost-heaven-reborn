# Reconstruction coverage

Evidence labels separate source-data parsing, binary analysis and runtime validation. Existing source-parse labels such as `PC-FREERIDE-DATA` and `PC-TOMMY-ANIMATION` map to the district research evidence index. The newer bounded district, Tommy experiment and original PC runtime labels map to a private evidence index snapshot with SHA-256 `ec4e734e297b18a3b902e55e40939f461ff2346a75b22535989b945f0eb11d11`; it lives outside the checkout. The REA/Ghidra dossier is static analysis of LS3DF.dll SHA-256 `e211c85009440d6c032f2074d79184f074a9a046574648745c2594b4cef178a6`; REA 6.7.0 at `6d356b84344659085f2b912857b5e27fe0160c9b` with Ghidra 12.1.4. The PS2 static cross-check is recorded as `PS2-E04`–`PS2-E07` in a private dossier with SHA-256 `dda776b7de4aac13b40643c92fa2d52850a647a0b2e85fb99730c1e9f62e3fc5`. The PS2 and REA dossiers do not validate runtime behavior. A parser proves a file can be read, not how the engine uses it. PC behavior is the baseline; PS2 is a platform cross-check.

The first PC binary dossier covers a narrow 4DS loader header, material branch, transform helper and 5DS version check; it reports 1,667 procedures in its LS3DF inventory profile, not complete subsystem coverage. Its dossier SHA-256 is `35ebd5fb6e6e55084b522b100ba1f4171d0839fb9e1d83c595b67546c8d528c3`; facts JSON SHA-256 is `cd2b4b9159d3854a250bd479766961dbffeb9ab50c656a2b9395bc19c54aca66`. The bounded PC animation API dossier SHA-256 is `3241f2cf41489ae2c061f56810256627e52245e97d1ee05cf3603d6a4368807b`; its loader, key-format and numeric-factor findings remain static hypotheses about runtime behavior. PS2-E05 verifies exact loading of original linked ELF main bytes with relocation application disabled; PS2-E06 checks selected EE p-code operations on synthetic inputs; PS2-E07 statically decompiles five original functions, including timing helpers. The cross-check confirms a shared numeric factor of 40 in PC and PS2 animation APIs but does not establish physical timing, runtime parity or whole-engine behavior. Full-system fidelity is not established until every subsystem has traceable PC binary evidence, PC runtime validation and PS2 cross-checks where applicable. Record unresolved differences and unknowns rather than filling them with assumptions.
